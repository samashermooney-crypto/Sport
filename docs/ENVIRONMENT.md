# Environment configuration

Use Node.js 24. Local development and tests use preview adapters, isolated PostgreSQL, Stripe test mode and no real recipient delivery. Never put secret values in `.env.example`, source control, command output or support tickets. Use a local ignored `.env` file or an environment secret store; `data/` files are local generated secrets and must stay untracked.

## Local development

Run `npm ci`, then export `COMPOSE_PROJECT_NAME=athlentry_ops PORT_OFFSET=1400` before `npm run db:up`, `npm run db:migrate` and `npm run dev`. The isolated OPS Postgres port is `6832`; Stripe mock, Mailpit API and SMTP use `13511`, `9425` and `2425`. Set `DATABASE_URL` and `DATABASE_ADMIN_URL` to the matching local database and roles when running scripts directly. For every Docker, database or Playwright command in this worktree, set both `COMPOSE_PROJECT_NAME=athlentry_ops` and `PORT_OFFSET=1400`.

The local stack binds only to loopback. Postgres trust authentication is for this disposable local Compose environment only. `DELIVERY_MODE=preview` routes email to Mailpit and keeps SMS and push in preview/fake adapters. Stripe requests must use test keys (`sk_test_`); live Stripe keys are rejected by the app. The local dev server creates ignored data-encryption and VAPID key files with owner-only permissions if they are absent. Do not use live Resend, Twilio, Checkr or Stripe credentials in tests or local development.

## Production deployment

The Render blueprint is a reference for two web instances, one worker and one isolated nightly backup cron at 02:00 UTC. The backup runner receives only the read-only dump URL, its dedicated encryption key and write-only credentials for the separate backup bucket; it does not receive application, payment, email or user-upload credentials. Cron storage is ephemeral, so the encrypted dump must upload successfully to private versioned object storage before the run exits successfully. Create managed PostgreSQL with point-in-time recovery retained for at least 14 days, a private versioned object bucket for user files and a separate private versioned backup bucket outside the application blueprint. Populate environment secrets only in the provider dashboard. `LEGAL_DOCS_APPROVED=false` intentionally prevents an unreviewed production launch. The pre-deploy command applies backward-compatible migrations before either new web instance receives traffic.

Keep application and admin database credentials distinct. Configure Sentry, signed payment/email/SMS webhooks, object storage, verified email sending domains and VAPID before enabling their features. Do not use the local Compose trust-auth configuration in a hosted environment. See [the operations runbook](ops/RUNBOOK.md) and [the custom-domain guide](ops/CUSTOM-DOMAINS.md).
